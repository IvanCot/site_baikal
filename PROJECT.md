# Контекст проекта

SSH-адрес GitHub: `git@github.com:IvanCot/site_baikal.git`.

Система внутреннего управления гостевым домом «У батюшки». Весь интерфейс,
документация и сообщения пользователю — на русском языке.

Основной стек: Python 3.12, Django 5.2, PostgreSQL, серверные шаблоны,
CSS и небольшой JavaScript, Docker Compose, Nginx. Завершённые бронирования сохраняются навсегда.

Две роли: администратор (admin) и владелец (owner). Владелец управляет номерами,
пользователями и аудитом. Администратор работает с гостями, бронированиями,
платежами и уборкой; данные номеров ему доступны только для просмотра. Управление
учётными записями доступно только владельцу, который также может сменить пароль
администратора. При миграции прежние администраторы становятся владельцами,
сотрудники — администраторами. Пароли остаются прежними.

Тариф номера за сутки хранится в Room.daily_rate; в Booking сохраняется его снимок.
Стоимость = тариф × разница местных календарных дат, минимум одни сутки. Изменение
тарифа номера не меняет сохранённые брони. Старые ручные суммы сохраняются при
редактировании без изменения номера или дат. Бельё и сопровождающие убраны из UI;
исторические поля и связи сохранены, чтобы не терять данные.

Паспортные данные и файлы не собираются. Миграция 0006 удаляет прежние
паспортные поля, файлы и связанные записи аудита. Исторические миграции
сохраняются для обновления существующих установок.

Оплаты сгруппированы по бронированию с сохранением каждого платежа. «Другое» требует
комментария, в том числе для предоплаты. Статистика: местные день, неделя с понедельника,
календарный месяц или всё время. Деньги — по paid_at, гости — сумма guest_count по
actual_check_in фактически начатых проживаний, без ожидаемых и отменённых броней.

Состояния брони: reserved → occupied → completed; reserved → cancelled.
Редактирование дат и состава доступно до завершения. Служебное состояние
номера хранится отдельно: ready, cleaning, unavailable. При выселении — cleaning.
Фактическое проживание имеет приоритет над плановыми датами на главной странице.

Проверка пересечений использует полуоткрытые интервалы [заезд, выезд),
транзакцию с блокировкой строки номера и ограничение EXCLUDE в PostgreSQL.
Смежные интервалы допустимы. Отменённые и завершённые брони не блокируют даты.

Основные маршруты: /, /calendar/, /bookings/, /guests/, /rooms/, /payments/,
/history/, /statistics/, /settings/, /audit/.
Операции изменения состояния принимают только POST и защищены CSRF.
