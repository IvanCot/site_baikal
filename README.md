# Байкал — управление гостевым домом

Рабочее веб-приложение для небольшого гостевого дома: номера, календарь занятости,
заезды и выезды, справочник гостей, расчёты, защищённые документы и история действий.
Весь интерфейс на русском языке. На главной видно, кто приезжает и уезжает,
кто живёт в каждом номере, сколько осталось оплатить и какие номера требуют уборки.

Репозиторий: `git@github.com:IvanCot/site_baikal.git`.

## Технологии и структура

Python 3.12, Django 5.2, PostgreSQL 16, Django ORM, серверные HTML-шаблоны,
адаптивный CSS, небольшой JavaScript без внешних CDN, Gunicorn, Nginx,
Docker Compose. Секреты и настройки поступают из окружения.

```text
config/                    Настройки Django, маршруты и WSGI
hotel/models.py            Пользователи, номера, гости, брони, платежи, документы, аудит
hotel/services.py          Транзакции заселения, выселения и отмены
hotel/forms.py              Формы и серверная валидация
hotel/validators.py         Проверка загружаемых файлов
hotel/views.py              Защищённые страницы и операции
hotel/migrations/          Схема и ограничения PostgreSQL
hotel/management/commands/  Создание администратора и демо-данных
hotel/tests/               Автоматические проверки
templates/                 Русский интерфейс
static/                    CSS и JavaScript
docker/                    Nginx и запуск контейнера
scripts/setup_env.py        Генерация локальных секретов
Dockerfile                 Образ приложения
docker-compose.yml         PostgreSQL, приложение, Nginx и постоянные тома
docker-compose.production.yml  Дополнительная конфигурация HTTPS
PROJECT.md                 Контекст и правила устройства проекта
```

## Первый запуск через Docker

Нужны Python 3.12+ для генерации конфигурации и запущенный Docker с Compose.
В Windows используйте `py -3.12` вместо `python`, если команда `python` недоступна.
В Linux/macOS команда может называться `python3`.

```bash
git clone git@github.com:IvanCot/site_baikal.git
cd site_baikal
python scripts/setup_env.py
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
```

Откройте [http://localhost:8080](http://localhost:8080) и войдите с созданным логином.
Пароль вводится скрыто. Учётная запись `createsuperuser` получает роль администратора.
Миграции и сбор статических файлов выполняются автоматически перед запуском Gunicorn.
Приложение запускается после готовности PostgreSQL; Nginx — после готовности приложения.

`setup_env.py` создаёт `.env` с отдельными случайными `SECRET_KEY` и паролем PostgreSQL.
Существующий файл не перезаписывается, секреты не выводятся. `.env` исключён из Git.
Для ручной настройки можно скопировать `.env.example` и заполнить пустые секреты.
Не меняйте `POSTGRES_PASSWORD` существующего тома без смены пароля в самой базе.

Альтернатива интерактивному созданию пользователя: перед первым запуском задайте
в `.env` `ADMIN_USERNAME`, `ADMIN_PASSWORD` и необязательный `ADMIN_EMAIL`.
Команда `bootstrap_admin` проверяет надёжность пароля и создаёт учётную запись
только при отсутствии логина. Пароль и права существующего пользователя не меняются.
После создания уберите `ADMIN_PASSWORD` из окружения и пересоздайте контейнер web.

## Демо-данные

После создания администратора, пока справочники и бронирования пусты:

```bash
docker compose exec web python manage.py seed_demo
```

Будут созданы №11, №12, Мансарда, №14, пять вымышленных гостей, текущее проживание,
заезд сегодня, будущая бронь, завершённая бронь и пять отдельных платежей.
Даты привязаны ко дню запуска в часовом поясе дома. Пароли и настоящие паспорта
не создаются. Повторное заполнение непустой базы запрещено.

## Ежедневная работа

1. На главной странице проверьте заезды, выезды, проживающих и уборку.
2. В календаре выберите диапазон дат. Клик по свободной ячейке открывает форму
   с номером, заездом в 14:00 и выездом следующего дня в 12:00; время можно изменить.
3. Найдите гостя по ФИО/телефону либо введите нового. Выберите сопровождающих.
   Нового сопровождающего предварительно создайте в справочнике «Гости».
4. Укажите гостей, стоимость, бельё и при необходимости предоплату и документы.
   Сохранение брони, нового гостя и предоплаты выполняется одной транзакцией.
5. Нажмите «Заселить» в плановый интервал. Для раннего заезда измените время брони.
   Номер должен быть подготовлен и не занят фактически другим гостем.
6. Добавляйте платежи по мере получения. Стоимость, оплаченная сумма и баланс
   рассчитываются через Decimal; переплата отображается отдельно.
7. Нажмите «Выселить». Запишется фактическое время, бронь уйдёт в историю,
   номер будет ожидать уборки. После подготовки нажмите «Уборка завершена».

Сервисное состояние «Требуется уборка» препятствует заселению, но допускает бронь
на будущее. «Недоступен» и отключённые номера не допускают новых действующих броней.
Состояние номера на главной учитывает фактическое проживание, даже при просроченном выезде.
Плановая занятость и точное время видны в календаре. Ячейка дня может показывать
две смежные брони; это не конфликт, если время выезда не позже следующего заезда.

Бронирования нельзя удалять: доступна отмена до заселения. Завершённые и отменённые
записи не редактируются. Финансовые ошибки исправляются в отдельных платежах с аудитом.
Номер или гость с историей не удаляется. Номер можно отключить.
Отключение и перевод в «Недоступен» допустимы после завершения или отмены
действующих бронирований, чтобы сохранить видимость заездов в календаре.

## Пользователи и права

Администратор управляет номерами, бронированиями, гостями, платежами, документами,
пользователями и видит журнал. Добавление и отключение учётных записей — в «Настройках».
Сотрудник видит главную, календарь, оперативные сведения бронирований и историю,
заселяет, выселяет и отмечает уборку. Финансы, документы, справочник гостей и управление
пользователями ему недоступны. Проверки применяются и к прямым запросам на сервер.
Свой доступ администратора отключить нельзя; последний администратор сохраняется.

Смена собственного пароля доступна в настройках. Сброс пароля другого пользователя:

```bash
docker compose exec web python manage.py changepassword ЛОГИН
```

## Защищённые документы

Файлы сохраняются под случайными именами в `/app/media/documents` внутри постоянного
тома `documents`. Nginx не имеет этого тома и отвечает 404 на `/media/`.
Скачивание `/documents/<id>/` требует входа и роли администратора, записывается в аудит,
возвращает `Cache-Control: private, no-store` и `Content-Disposition: attachment`.
URL содержит идентификатор записи, а не пользовательский путь к файлу.

Разрешены JPG/JPEG, PNG, WEBP и PDF, до пяти файлов за один запрос и до 10 МБ на файл.
Для изображений проверяются содержимое и соответствие формата расширению,
для PDF — сигнатура. HTML, SVG и исполняемые файлы запрещены. Сигнатура PDF
не является антивирусной проверкой; открывайте документы в обновлённом просмотрщике.
Права и CSRF проверяются сервером. Содержимое документов и секреты в логи не пишутся.

## Настройки рабочего сервера

Для реальных персональных данных используйте HTTPS. Локальный `.env` создаётся
с `DEBUG=True` для проверки на localhost. Перед размещением измените:

```dotenv
DEBUG=False
ALLOWED_HOSTS=hotel.example.ru
CSRF_TRUSTED_ORIGINS=https://hotel.example.ru
SECURE_SSL_REDIRECT=True
TIME_ZONE=Asia/Irkutsk
```

Часовой пояс по умолчанию — Иркутск (Байкал), можно задать другой IANA timezone.
Все даты в базе хранятся с учётом часового пояса; ввод и отображение — в местном времени дома.

Поместите действительные TLS-сертификаты в `certs/fullchain.pem` и `certs/privkey.pem`.
Каталог исключён из Git и Docker build. Запуск с HTTPS:

```bash
docker compose -f docker-compose.yml -f docker-compose.production.yml up -d --build
docker compose exec web python manage.py check --deploy
```

Домен направьте на сервер; откройте порт 443. HTTP перенаправляется на HTTPS.
В режиме `DEBUG=False` включены secure cookies и HSTS. Порт приложения и PostgreSQL
не публикуются. Nginx перезаписывает `X-Forwarded-Proto` своим значением, поэтому
внешний клиент не может подделать защищённый протокол. При использовании другого
TLS-прокси адаптируйте конфигурацию и допускайте заголовок только от доверенного прокси.
Продление сертификатов выполняет оператор сервера; после обновления выполните
`docker compose exec nginx nginx -s reload`.

Храните резервные копии отдельно от сервера с ограниченным доступом. Устанавливайте
обновления зависимостей и ОС. Ограничьте доступ к внутреннему приложению VPN / сетью
организации при необходимости. Не публикуйте DEBUG-сервер с настоящими паспортами.

## Резервная копия PostgreSQL

Формат custom dump не повреждается перенаправлением бинарных данных в PowerShell:

```bash
docker compose exec db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/baikal.dump'
docker compose cp db:/tmp/baikal.dump ./baikal.dump
```

Восстановление выполнять в **новую пустую базу**, созданную в отдельном окружении
с PostgreSQL той же или более новой версии. Не накатывайте миграции до восстановления:

```bash
docker compose up -d db
docker compose cp ./baikal.dump db:/tmp/baikal.dump
docker compose exec db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --no-owner --exit-on-error /tmp/baikal.dump'
docker compose up -d --build
```

Не используйте `--clean` поверх рабочей базы: история бронирований защищена от удаления.
Перед восстановлением сохраните текущее состояние и протестируйте восстановление отдельно.
Файлы документов не входят в дамп PostgreSQL. Создание архива файлов:

```bash
docker compose exec web python -c "import shutil; shutil.make_archive('/tmp/baikal-documents', 'gztar', '/app/media')"
docker compose cp web:/tmp/baikal-documents.tar.gz ./baikal-documents.tar.gz
```

Для согласованной копии базы и файлов на время резервирования закройте доступ через Nginx
(`docker compose stop nginx`), дождитесь завершения текущих операций и затем
снова запустите его (`docker compose start nginx`). Резервируйте также `.env` безопасным
способом. Восстановление документов: скопируйте архив в web, проверьте список путей,
распакуйте в `/app/media` с правами пользователя app. Архивы содержат персональные данные.

## Обновление и полезные команды

### Что отправляется в GitHub

В `git@github.com:IvanCot/site_baikal.git`, ветку `main`, отправляются исходники
приложения: `config/`, `hotel/` вместе с миграциями и тестами, `templates/`,
`static/`, `scripts/`, `docker/`, файлы Docker Compose, `Dockerfile`,
`requirements.txt`, `.env.example` и документация.

Реальные `.env`, пароли, сертификаты, база, загруженные паспорта, резервные копии
и временные файлы в GitHub не отправляются. Они исключены через `.gitignore`.
Каталог `backups/` предназначен для локальных резервных копий; не используйте
репозиторий как хранилище персональных данных.

После изменений исходников на компьютере разработчика:

```bash
git status
git add .
git diff --cached --stat
git commit -m "Описание изменений"
git push origin main
```

Перед коммитом проверьте список добавленных файлов. На VPS исходники скачиваются
из GitHub через `git clone` при первом запуске и `git pull --ff-only` при обновлениях.
Рабочий `.env` создаётся отдельно на VPS. База и документы остаются в постоянных
томах Docker на VPS; резервные копии сохраняются отдельно. Сотрудники работают
с сайтом через браузер, доступ к GitHub им не требуется.

### Обновление приложения на VPS

Перед обновлением сделайте копию базы и документов. Том PostgreSQL и документы
сохраняются при пересоздании контейнеров. Команда `down -v` удаляет данные — не используйте её
для обычного обновления.

```bash
git pull --ff-only
docker compose up -d --build
docker compose restart nginx
docker compose ps
docker compose logs --tail 100 web
docker compose exec web python manage.py migrate
docker compose exec web python manage.py test --verbosity 2
docker compose exec web python manage.py check --deploy
docker compose exec nginx nginx -t
```

Тесты запускаются в отдельной временной базе. Пользователю PostgreSQL для них нужны
права `CREATEDB`; стандартный контейнер даёт их при инициализации. Проверяются конфликты,
смежные интервалы, финансовые расчёты, переходы статусов, уборка, роли, CSRF,
защищённые файлы, формы и страницы. Отдельные тесты PostgreSQL проверяют EXCLUDE
для массовой вставки и запрет удаления напрямую в SQL.
Также проверяются одновременное создание двух конфликтующих броней и повторное
заселение из параллельных запросов.

Для дополнительной проверки интерфейса установите `npm install --no-save playwright`.
Скрипт `node scripts/verify_ui.cjs путь-к-файлу.json` принимает локальный JSON с полями
`username` и `password` администратора, проверяет 10 страниц при ширине 1440, 768 и
390 пикселей, поиск гостя, предзаполнение календаря и мобильное меню. Для поиска
нужны демо-данные. `UI_BASE_URL` задаёт адрес (по умолчанию localhost:8000),
`UI_OUTPUT_DIR` — каталог снимков. Chrome должен быть установлен. Файл с паролем
держите вне Git; скрипт не выводит его содержимое.

## Локальная разработка без контейнеров

Основной рабочий режим использует PostgreSQL. Для быстрой разработки на Windows:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/setup_env.py
docker compose up -d db
```

При работе Python с PostgreSQL вне Compose понадобится отдельный локально доступный
PostgreSQL; стандартный Compose намеренно не публикует порт базы.
Для быстрой проверки UI можно использовать SQLite:

```powershell
$env:USE_SQLITE='True'
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
.\.venv\Scripts\python.exe manage.py test
```

SQLite — только вспомогательный локальный режим: без блокировок строк, EXCLUDE
и SQL-триггера PostgreSQL. Не используйте его в рабочем многопользовательском режиме.
В Compose `USE_SQLITE=False` устанавливается принудительно. `.env` должен содержать
`DEBUG=True` для локального HTTP.

Архитектурные решения опираются на официальную документацию Django:
[блокировки select_for_update](https://docs.djangoproject.com/en/5.2/ref/models/querysets/#select-for-update),
[защита приложения](https://docs.djangoproject.com/en/5.2/topics/security/).
